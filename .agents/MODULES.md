- [07-react-query](07-react-query/SKILL.md): Query keys, invalidação e paginação/infinite scroll com TanStack Query. Use when: query, mutation, cache, query keys, infinite scroll, staleTime.
- [08-auth](08-auth/SKILL.md): Autenticação segura: access token em memória, refresh via cookie httpOnly. Use when: login, logout, JWT, refresh token, sessão, autenticação.

- [11-error-handling](11-error-handling/SKILL.md): ErrorBoundary, Sentry com scrubbing de PII, toasts e mensagens de erro. Use when: erro, ErrorBoundary, Sentry, toast, mensagens de erro.

- [18-websockets](18-websockets/SKILL.md): Cliente WebSocket com autenticação pós-handshake e reconexão com backoff. Use when: websocket, realtime, reconexão, autenticação de socket.
- [19-solid](19-solid/SKILL.md): Princípios SOLID aplicados às camadas Page → Hook → Transporter. Use when: SOLID, responsabilidade única, refactor, composição.

- [23-accessibility](23-accessibility/SKILL.md): WCAG 2.2 AA por omissão: contraste, foco, formulários, rotas. Use when: acessibilidade, a11y, contraste, WCAG, screen reader.
- [24-ci-quality](24-ci-quality/SKILL.md): Lint, type-check, testes e auditoria de dependências automatizados em CI. Use when: CI, lint, ESLint, GitHub Actions, pipeline, dependabot.
- [25-e2e](25-e2e/SKILL.md): Fluxos críticos cobertos por testes end-to-end com Playwright. Use when: e2e, Playwright, fluxo crítico, teste end-to-end.
- [26-privacy](26-privacy/SKILL.md): RGPD por construção: consentimento, minimização de dados, telemetria sem PII. Use when: RGPD, privacidade, consentimento, cookies, GDPR.
- [27-data-table](27-data-table/SKILL.md): Padrão de tabela de dados para back-office: URL state, seleção, virtualização, export. Use when: tabela, data table, paginação, ordenação, seleção em lote, exportar CSV.
- [28-security-verification](28-security-verification/SKILL.md): Prova, com testes e gates de CI, que a superfície de segurança do cliente React web está blindada — segredos fora do bundle, token só em memória, sinks de XSS controlados, headers/CSP do host, SCA. Não é auditoria de código (isso é 17-security): é verificação de runtime/build que falha quando o controlo desaparece. Use when: verificação de segurança web, segredos no bundle, token em localStorage, XSS sink, dangerouslySetInnerHTML, CSP do frontend, security headers, npm audit, gate de segurança no CI, blindar o frontend.
- [29-pentest](29-pentest/SKILL.md): Agente de pentest ativo/operacional: identifica e valida vulnerabilidades reais num alvo em execução. Complementa 17-security (17, auditoria estática de código) e 28-security-verification (28, prova que o cliente protege). Aqui testa-se o alvo DINAMICAMENTE: reconhecimento, bypass de autenticação (brute force, SQLi, JWT, session fixation), injeções (XSS, SSRF, IDOR), privilégios, hardening (headers/CORS/CSP), e gera relatório. Só em ambientes autorizados (laboratório próprio). Use when: pentest, teste de segurança ativo, brute force, sql injection, jwt tampering, bypass autenticação, xss, ssrf, idor, security headers, hardening, teste de intrusão, validar segurança.
- [30-simplify](30-simplify/SKILL.md): Simplifica código e decisões com mentalidade YAGNI/ponytail: o melhor código é o que não foi escrito. Antes de escrever, desce a escada de simplificação (YAGNI → reutilizar → stdlib → nativo → dependência → uma linha → mínimo que funciona). Sem nunca cortar validação, segurança ou acessibilidade. Baseado no repo github.com/dietrichgebert/ponytail. Use when: simplificar, código mínimo, remover over-engineering, YAGNI, reutilizar em vez de recriar, menos código, simplificar componente, remove lines, simplify.
- [31-code-review](31-code-review/SKILL.md): Metodologia de code review de Pull Request com foco em ALTA PERFORMANCE e CIBERSEGURANÇA. Checklist por camada: security (bypass de autenticação, XSS, tokens, CORS, headers), performance (re-renders, bundle, queries), e regras do sistema (20-rules). Usar ao rever PRs antes de merge. Use when: code review, rever PR, revisão de código, pull request review, audit de performance, audit de segurança de código, diff review.
- [32-ci-cd](32-ci-cd/SKILL.md): Continuous Delivery/Deployment (CD): promover builds imutáveis do CI para produção com estratégia segura. Foca no que 24-ci-quality NÃO cobre — ambientes (dev/staging/prod), gate de promoção, blue-green/canary, e2e+axe no staging, aprovação, observabilidade pós-deploy, rollback e verificação de segurança no pipeline. Complementa 24-ci-quality (qualidade/lint/testes no PR). Use when: CD, deployment, deploy, ambientes, staging, produção, promote, blue-green, canary, release, pipeline de deploy, rollback, enviar para produção.
- [33-orchestration](33-orchestration/SKILL.md): Distribui tarefas delimitadas entre planeamento, implementacao e revisao, com contexto minimo e medicao do custo total. Usar ao delegar trabalho ou definir estrategia de modelos.
- [34-backend-fastapi](34-backend-fastapi/SKILL.md): Backend Python FastAPI do Housekeeping e contrato FE-BE (Pydantic v2, auth, erros, Opera, testes). Fonte de verdade do contrato de dominio; manter sincronizada com types, transporters e config/constants.ts do FE. Use when: backend, FastAPI, Pydantic, API, endpoint, contrato FE-BE, modelo de dados, migracao, Opera sync.
- [99-example](99-example/SKILL.md): Exemplo canónico e validado empiricamente de um domínio completo (`contacts`). Use when: exemplo completo, referência, copiar domínio, dúvida entre regra e exemplo.
